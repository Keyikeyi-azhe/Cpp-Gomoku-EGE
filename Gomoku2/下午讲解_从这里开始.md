# Gomoku2：下午讲解用的阅读路线

这次修改的目标是让入口、输入、动作和绘图容易找到。界面、规则、三个AI难度、联网协议和存档格式保留。

先记住：头文件不会自己“运行”。`#include`只是把文件内容提供给编译器；程序真正的执行路线由函数调用决定。这个工程仍由客户端main.cpp和服务器server_main.cpp分别编译成两个程序。

## 先掌握四个状态

|变量|表示什么|你讲解时举的例子|
|---|---|---|
|page|正在显示哪个页面|MAIN_MENU主菜单，MODE_MENU模式菜单，GAME_PAGE棋盘|
|dialog|当前是什么询问|NO_DIALOG无询问，FINISHED_SAVE保存终局，NAME_SAVE命名，AGAIN再来一局|
|game.turn|轮到谁落子|1黑、2白；普通落子结束后切换|
|game.result|对局结果|0未结束、1黑胜、2白胜、3平局|

game.cells是15×15棋盘，0表示空。game.moves是按时间保存的一手手历史，供绘图、悔棋、存档和复盘使用。

## 每个文件负责什么

|文件|职责|你应该找什么|
|---|---|---|
|main.cpp|程序启动后每轮做什么|主循环，不用在长文件里寻找鼠标处理|
|game_input.h|窗口和鼠标输入、初始化与释放|processMouseMessages / handleWindowCloseRequest|
|game_actions.h|按钮对应的操作与页面变化|act / handleMenuAction / newGame / saveGame|
|game_draw.h|根据状态绘制页面|render / drawGame|
|ui_common.h|共享变量、枚举、按钮和基本绘图|page / dialog / game / Button / hitButton|
|game_logic.h|不依赖图形界面的五子棋规则|LocalGame / Move / reset / place / wins / undo|
|record_store.h|存档读取、校验、编码、写入|GameRecord / readRecord / writeRecord|
|replay_logic.h|独立展示盘和播放时间|ReplayPlayer / open / seek / tick|
|ai_engine.h|AI后台任务及搜索|AIWorker / AISearch|
|online_ui.h|联网按钮、消息和本机保存流程|onlineAction / updateOnline|
|network_protocol.h|服务器验证指令、维护房间|NetState / apply|
|network_transport.h|TCP连接、消息队列和收发|NetClient / NetSocket|
|server_main.cpp|独立服务端入口|监听、握手、apply、广播|
|match_metadata.h|结束原因与结果一致性|validResult / reasonText|

共享区先提供状态和基础函数；动作区调用规则、存档、复盘或联网；输入区调用动作区；显示区读取状态。它们仍是一个小型客户端编译单元，尚未改成多cpp加extern的链接组织，方便继续使用原Dev-C++工程和单文件编译方式。

## 第一次讲：从启动到进入棋盘

1. main调用initializeProgram：开窗口、读图片、创建输入框，然后进入循环。
2. 每轮处理窗口消息、网络更新、关闭请求、鼠标，再更新AI/复盘，最后render重画。
3. render看到page=MAIN_MENU，登记“开始游戏”按钮；drawButtons画按钮。
4. 鼠标按下：记住pressed。松开：再次hitButton，只有同一个按钮才act(hit)。
5. act把菜单按钮交给handleMenuAction。A_START把page改为MODE_MENU。
6. A_LOCAL把gameMode改成LOCAL_TWO，调用newGame。
7. newGame调用game.reset：盘面清零、历史清空、turn=1、result=0；page=GAME_PAGE、dialog=NO_DIALOG。
8. 下一次render根据新page画棋盘。

你可以这样说：“按钮没有直接画出下一页，它先改变page；绘图函数下一次读到这个状态，就画对应页面。”

## 第二次讲：从点击交点到黑胜

1. processMouseMessages先调用humanCanMove，确认当前允许落子。
2. boardCell把鼠标像素换成交点编号cell。row=cell/15，col=cell%15。
3. 按下和松开交点一致，单机模式就调用game.place(row,col)。
4. place先拒绝终局、越界、已占用，再写cells[row][col]=turn。
5. 创建Move，分别记录row、col、stone，然后放进moves。
6. wins从最后一颗棋子出发，沿竖直、水平、两条斜线分别向两端数同色棋子。
7. >=5：result=当前颜色；否则满225手：result=3；否则1黑换2白，2白换1黑。
8. place返回true只表示落子成功。输入区还要检查result，非0才dialog=FINISHED_SAVE。
9. drawGame读取result和moves，画胜利横幅、连线金圈和保存询问。

|总手数|颜色|行列|落子后的turn|result|
|---|---|---|---|---|
|1|黑|(7,3)|2|0|
|2|白|(8,3)|1|0|
|3|黑|(7,4)|2|0|
|4|白|(8,4)|1|0|
|5|黑|(7,5)|2|0|
|6|白|(8,5)|1|0|
|7|黑|(7,6)|2|0|
|8|白|(8,6)|1|0|
|9|黑|(7,7)|1|1|

第9总手才是黑棋第5颗。终局不换手，所以黑胜后turn仍为1。

## 第三次讲：保存并返回

1. FINISHED_SAVE询问中的“是”对应A_YES，act交给handleDialogAction。
2. handleDialogAction看到当前dialog，调用beginName。
3. 新局currentName为空：dialog=NAME_SAVE，显示输入框；savingFinished=true。
4. 输入名字点击保存：A_SAVE交给handleSaveAction，用GetWindowTextW取文字，再saveGame。
5. saveGame检查名字，创建GameRecord，复制棋局、模式、难度、颜色和名称。
6. result非0，record.replay=true，写成data/replays/*.greplay。
7. writeRecord先encodeRecord生成文本，再parseRecord自检；写.tmp、刷新、关闭，然后改成正式名。
8. 成功才调用savedSuccessfully，隐藏输入框，dialog=AGAIN。
9. “要不要再来一局”选择否：handleDialogAction调用mainMenu，page=MAIN_MENU、dialog=NO_DIALOG。

未结束时退出保存：保存的是unfinished/*.gsave，成功直接回菜单；命名取消则回保存询问。保存失败不清掉当前棋局，允许重试。

## 老师追问时，先解释这几个区别

- act只负责把按钮交给对应组：handleMenuAction、handleGameAction、handleDialogAction、handleSaveAction、handleReplayAction、handleListAction。各组返回true表示已经认领动作，false表示交给下一组。
- 同一个“是”按钮编号A_YES，由dialog决定是保存、重开、删除还是再来一局。
- game是对象，LocalGame是它的类型。game.place(...)是在这个对象上调用方法。
- game.moves是vector：可增长的历史列表。push_back追加，back读最后一项，pop_back删最后一项，size读数量。
- const Button& b是当前按钮的只读别名，不复制整个按钮；这类引用保留，因为它比复制大对象合适。
- sizeof、函数指针、Win32句柄和强制转换属于平台接口细节。主流程已经移出这些细节，遇到时解释用途即可，不必声称它们是普通C++数组或整数。
- 人机：玩家落子仍走place，电脑在副本上计算，主线程取结果再place。generation是任务版本，用来丢弃重开/悔棋之前的旧答案。
- 联网：本机只发MOVE，服务端apply检查并落子，广播STATE后客户端复制权威棋盘。不会发送后立即自己修改game。
- 重开/悔棋需要双方确认；退出/认输只需发起者本人确认。联网archiveStage和本地dialog不是同一个变量。
- 标题栏×由gameWindowProc记请求，主循环处理。普通本地模式×会直接退出；要保存请点棋盘里的退出。

## 讲解的固定顺序

先main.cpp，再game_input.h中的processMouseMessages，再game_actions.h中的act/handleMenuAction/newGame，再game_logic.h中的place/wins，最后回到game_actions.h中的beginName/saveGame/handleDialogAction。绘图的render/drawGame只在说明“状态如何显示出来”时插入。

不要从ui_common.h第一行一直背到服务器最后一行。先完整解释一个可演示场景，再分开解释存档、复盘、人机、联网。
