# Gomoku2 第二版阅读地图

这份地图对应重新整理后的源码。先看入口函数的主线，再进入当前模式对应的函数；不要把所有模式的内部代码混着讲。

## 阅读顺序

1. `main.cpp`：初始化、主循环、退出清理。
2. `ui_common.h`：页面、弹窗、共享状态、Button 和按钮工具。
3. `game_logic.h`：Move、LocalGame、初始化、落子、判胜、悔棋。
4. `game_input.h`：初始化入口、鼠标输入入口。
5. `game_actions.h`：按钮操作分组、开局、存档、AI 更新入口。
6. `game_draw.h`：render、drawGame，再读对应模式的面板。
7. `match_metadata.h`：对局时间、结束原因、结果合法性。
8. `record_store.h`：存档格式、读取、校验、写入。
9. `replay_logic.h`：复盘播放、暂停、跳步。
10. `ai_engine.h`：AI 线程、评分、搜索。
11. `network_protocol.h`：联网阶段和服务器规则。
12. `network_transport.h`：连接与消息收发。
13. `online_ui.h`：联网操作、状态同步、房间与对局显示。
14. `server_main.cpp`：服务器运行入口。

## 初始化主线：initializeProgram

```text
setProgramDirectory：找到 exe 文件夹，设置资源查找目录
  → createGameWindow：创建游戏窗口
  → loadGameImages：读取图片、菜单动画
  → createInputControls：创建命名、地址、端口输入框
  → 安装关闭回调，准备存档目录
  → 返回初始化是否成功
```

这些都是启动准备，不是落子逻辑。目录失败会立即返回；图片或输入框失败则返回初始化失败，由 main 清理已创建的资源。

## 输入主线：processMouseMessages

```text
取出一个鼠标消息
  ├─ 列表页滚轮 → scrollRecordList
  ├─ 左键按下 → rememberMouseDown：只记录目标
  └─ 左键松开 → finishMouseClick：判断按下、松开是不是同一个目标
                     ├─ 按钮 → act
                     └─ 棋盘交点
                          ├─ 联网 → onlineMove：发送请求，等待服务器确认
                          └─ 单机/人机 → placeLocalStone：立即调用 game.place
```

`placeLocalStone` 只处理人的本地落子。电脑落子由 `receiveAIResult` 接收并应用。

## 总绘图主线：render

每一帧都先清掉旧按钮，再选择一个页面来画，最后统一画按钮和临时提示。

```text
buttons.clear
  → 按 page 选择
      ├─ 菜单 → drawMenuPage
      ├─ 联网房间 → drawOnlinePage
      ├─ 游戏/复盘 → drawGame
      └─ 存档/复盘列表 → drawRecordListPage
  → drawButtons：真正画按钮
  → drawNotice：未过期时显示短提示
```

`addButton` 登记位置、文字、编号和可用状态；不会执行按钮动作。动作由输入函数调用 `act` 执行。

## 棋盘绘图主线：drawGame

入口先选择显示哪一个棋盘：复盘用 `replayPlayer.board`，对局用 `game`。随后所有模式都会调用这三个函数：

```text
drawBoard：背景、棋盘、已有棋子
  → drawGameResult：未结束就不画结果；结束后显示横幅和获胜金圈
  → drawSidebarBase：右侧浅米色底板
```

接着只进入一条模式路线：

| 当前情况 | 接下来调用 |
|---|---|
| 复盘 | 联网棋谱额外调用 drawOnlineBoardExtras，然后 drawReplayPanel |
| 实时联网 | drawOnlineBoardExtras → drawOnlineSidebar |
| 人机 | drawAIPanel |
| 单机双人 | drawLocalPanel |

`drawLocalPanel` 的主线：状态 → 操作按钮 → 当前询问。

`drawAIPanel` 的主线：状态 → 难度和执棋颜色 → 操作按钮 → 当前询问。

`drawOnlineBoardExtras` 只给联网及联网复盘使用。半透明预览只在实时联网且可以落子时出现；最后一手标记要求至少有一手棋。

`drawGameResult` 不判定谁赢，胜负已由规则层或服务器确定。它只读取结果；不是认输、不是平局时检查四个方向，为连成五颗以上的棋子画金圈。

## 人机更新：updateAI

```text
receiveAIResult：收回结果，拒绝旧对局的结果，合法时落子
  → startAIIfNeeded：仅轮到电脑且没有线程时启动计算
```

`isComputerTurn` 集中判断：游戏页面、无弹窗、人机模式、未结束、轮到电脑。其他模式不会启动 AI。结果仍需收回清理，因此不能简单在 updateAI 顶部跳过所有非人机情况。

## 联网房间显示：drawOnlinePage

先画共同背景、底板、标题，然后按 `netStage` 选择：

| netStage | 调用函数 | 用户看到什么 |
|---|---|---|
| 0 | drawOnlineMenu | 创建/加入房间 |
| 1 或 2 | drawOnlineConnectionForm | 房主端口或朋友地址/端口 |
| 3 | drawOnlineConnecting | 连接中、取消连接 |
| 5 | drawOnlineEndNotice | 离开/断线提示 |
| 其余正常等待状态 | drawOnlineLobby | 双方准备、执棋身份、离开房间 |

## 联网对局显示：drawOnlineSidebar

先调用 `drawOnlineStatus` 显示状态、身份、步数、延迟，再选一种情况：

```text
正在离开 → 只提示正在通知对方
保存阶段 archiveStage != 0 → drawOnlineArchivePanel
其余 → drawOnlinePlayPanel
```

联网消息由 `updateOnline` 读取。它检查连接和离开超时，并区分心跳、延迟、欢迎、确认、错误、事件和 STATE。

STATE 交给 `applyOnlineStateMessage`：校验消息 → 替换权威状态 → 同步棋盘 → 处理离开通知 → 必要时开始保存询问。服务器确认以前，客户端不能擅自把预览变成正式棋子。

## 不要混淆

- 文件的阅读顺序，不等于程序实际执行顺序；执行顺序由调用决定。
- `draw...` 显示当前状态；`act` 和规则函数才改变业务状态。
- `page` 是页面，`dialog` 是询问，`gameMode` 是对局模式。
- `game.turn`：1 黑、2 白；`game.result`：0 未结束、1 黑胜、2 白胜、3 平局。
- 黑方下五手获胜，交替落子时总共通常是九手：黑五手、白四手。
