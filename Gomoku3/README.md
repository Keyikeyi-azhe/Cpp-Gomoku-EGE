# 五子棋：单机、人机、联网与复盘

当前联网增强版使用**协议2、联网复盘v4**。双方都需要更新 `Gomoku.exe` 和 `GomokuServer.exe`；协议1旧版会收到版本不兼容提示。Dev-C++编译方法不变：先编译 `GomokuServer.dev`，再编译 `Gomoku.dev`，单文件链接参数仍为原EGE参数加 `-lws2_32 -liphlpapi`。仍不支持中断对局重连。

双击 `Gomoku.exe` 启动。窗口为1800×1350，菜单使用原素材90帧动画、楷体文字。

- 初始按钮：开始游戏、继续游戏、复盘、退出。
- 点击开始游戏：保留同一背景，按钮文字变为单机对弈、人机对弈、联网对弈、算了不玩了。
- 初始菜单的退出按钮关闭程序；也可随时使用窗口关闭按钮。
- 点击“算了不玩了”返回初始菜单。
- 点击单机对弈进入双人棋盘，黑先白后，五子及以上连线获胜；满盘无胜者为平局。
- 悔棋撤回最后一手；重开先询问，确认后清空棋盘。
- 对局退出时询问是否保存残局；结束时询问是否保存复盘，再询问是否再来一局。
- 所有询问、命名期间锁定棋盘和对局按钮。询问和输入框位于右侧，不遮挡棋盘。
- 可操作按钮按下时整个圆角区域变浅灰，松开复原。
- 获胜时显示大幅红金横幅，并用金色圆圈标记胜利连线。
- 继续游戏和复盘展示对应列表，右侧显示单机/人机/联网模式，并可确认永久删除文件；删除后自动补位，滚轮可滚动。
- 继续游戏载入棋盘、落子历史和回合；续局保存沿用原名称并更新原文件。续局完成后保存为同名复盘，成功后移除原残局。新开棋局首次保存仍需要命名。
- 复盘从空棋盘开始；1x每3秒一子、2x每1.5秒一子，支持暂停、继续。播放时隐藏上下步，暂停时可单步；播放结束自动停止。退出前暂停并询问，选择否也保持暂停。复盘过程不修改存档。
- 人机对弈提供简单、一般、困难，开局先选执黑或执白（黑先）。悔棋撤回玩家最近一回合，电脑已应答时同时撤回应答；电脑单独先手不能悔棋。
- 没有对应存档时在主菜单显示“暂无存档”两秒。联网功能及操作见下文；联网未完记录只能复盘，不能恢复继续。

未完成棋局保存在 `data/unfinished/*.gsave`，完整复盘及联网未完复盘保存在 `data/replays/*.greplay`。中文名称最多24字，文件内保存UTF-8名称、模式、难度、玩家颜色、黑白落子顺序、坐标、回合和结果。新棋局同名不会覆盖旧记录；载入的残局按原文件更新。保存失败保留当前棋局，可重试或取消。

新版存档以 `GOMOKU_LOCAL_SAVE 2` / `GOMOKU_LOCAL_REPLAY 2` 为文件头；兼容上一阶段v1单机数据。读档逐手重建和验证，拒绝越界、重复落点、颜色或回合错误、胜后继续落子、伪造结果等坏档。当前不含多局制和30秒计时。联网对局中的窗口关闭按钮会先走退出及保存确认；本地模式需要保存时请使用棋盘右侧“退出”。

AI采用Win32后台线程，不在绘图线程搜索。简单档采用攻防棋型分数和近优随机；一般档采用Negamax、Alpha-Beta、最多4层迭代加深，预算500ms；困难档最多8层、预算2000ms，并使用Zobrist置换表、历史排序与上一轮最佳着法优先。全部档次先检查一步成五和防守，普通候选取已有棋子周围两格。预算不足时采用上一次完整深度的合法结果，实际完成深度取决于局面及电脑速度。询问、读档、悔棋和重开会取消旧搜索，过期结果不会落入新棋盘。

编译：在 Dev-C++ 5.11 中打开 `Gomoku.dev` 工程（不要只打开 main.cpp），选择 TDM-GCC 4.9.2 的64位编译器，再执行“重新编译全部”，随后运行。工程已经配置 C++11、GBK 输入编码和 EGE 链接参数。

为兼容本机旧版 Dev-C++ 编辑器，`main.cpp` 使用 **GBK（简体中文 Windows 的 ANSI，代码页936）** 编码，保留中文注释。工程明确设置 `-finput-charset=GBK`。界面文字采用 `L"\uXXXX"` Unicode 转义，并附中文注释；这使当前源码在单文件编译未携带 GBK 参数时也能正确编译中文文字。宽字符接口和楷体显示保持不变。

单文件方式：打开 `main.cpp`，使用 TDM-GCC 4.9.2 64-bit Debug 配置，在原 C++11 与 EGE 链接参数后新增 `-lws2_32 -liphlpapi`，按 F11 编译运行，输出为 `main.exe`。这两个新增参数分别链接 Windows 网络库与网卡地址查询库。已按该配置验证不加 `-finput-charset=GBK` 也能编译。工程方式输出为 `Gomoku.exe`。两者都在素材目录旁运行。

如果转换前已在 Dev-C++ 打开源码，请关闭旧标签页并且不要保存乱码内容，然后重新打开工程和源码；如果出现外部文件修改提示，选择从磁盘重新加载。后续编辑保存时保持 GBK/ANSI 编码。使用其他编辑器修改该文件时，也必须按 GBK 读取和保存，不能直接以 UTF-8 覆盖。

备用命令行构建为 `powershell -ExecutionPolicy Bypass -File .\build.ps1`，使用相同的本机 Dev-C++ 编译器和 GBK 参数；不需要改用其他 IDE。

`assets` 目录联接到本工作区原材料，运行时以exe所在目录查找素材。若单独复制程序，请同时复制实际 `assets` 文件夹。90帧图像解码后约834MiB，启动时预加载，播放期间不反复读盘。

窗口固定为1800×1350，已撤回最大化和动态缩放尝试。棋盘和棋子源素材保持原尺寸，在对局页面按1.5倍显示。背景使用实际存在的 `bg_a.png`。询问按钮沿用 `assets/ui/button_320x80.png`。

`main.cpp` 引入 `game_logic.h`（规则）、`record_store.h`（存档验证与原子写入）、`replay_logic.h`（播放游标）、`ai_engine.h`（搜索与后台线程）。仍可直接编译 main.cpp；源文件使用GBK并附中文注释。Python和PowerShell只用于开发辅助与测试，游戏运行不依赖它们。

核心检查位于 `tests/core_tests.cpp`、`tests/stage_tests.cpp`。本阶段窗口流程检查为 `tests/stage_ui.ps1`，每次在独立的 `tests/ui_run_<随机编号>` 中建立测试存档，避免改动用户棋局；上一阶段的 `tests/ui_smoke.ps1` 保留作历史参考，其坐标和流程不再适用新版。


## 本版联网操作

1. 两台电脑先连接 Tailscale，建立设备共享/访问权限。游戏本身不操作 Tailscale 账号。
2. 房主点击“开始游戏 → 联网对弈 → 创建房间”，端口默认5000。点击创建后自动隐藏启动同目录的 `GomokuServer.exe`。等待页显示 Tailscale 地址和端口；检测不到时从 Tailscale 客户端核对复制。服务端监听IPv4各接口，房主 Windows 防火墙需允许该程序的 TCP 入站，建议限定朋友的 Tailscale 地址。
3. 朋友点击“加入房间”，输入房主IPv4地址和相同端口，再点击连接。可取消连接；输入错误、超时、端口占用、房间已满、版本不符会提示并保留输入。
4. 房主固定执黑，朋友固定执白。双方点击准备后开局；开局前可取消准备或确认离开。朋友在开局前离开后，房主可继续等待另一人加入。
5. 只有本方回合才能落子；服务端确认后双方才更新。合法交叉点显示半透明本方棋子预览，最后一手有小圆圈标记；询问、非本方回合、等待确认时不显示预览。点击后显示“落子确认中”，较长等待时提示网络较慢。右侧显示心跳测得的往返延迟。窗口继续采用1800×1350和楷体。
6. 请求重开先由本机确认，再询问对方。整个询问期间双方棋盘锁定。对方拒绝后，发起方看到“对方拒绝了你的重开请求”两秒，原棋局和轮次继续。对方同意后，双方独立选择保存这局未完复盘，双方完成选择后才清空棋盘。
7. 获胜/平局后，双方独立选择是否保存到各自电脑，命名最多24字、默认含时间，同名附编号不覆盖。右侧区分对方正在选择保存、正在命名、正在决定再战、已经同意再战；只同步阶段，不传输名称。双方都同意才开始，等待期间可取消退出。点击“否”时对方明确看到“对手拒绝了再来一局”；先同意后取消等待则显示“对手取消了再来一局”。对方已处理完保存时显示两秒后返回主界面；仍在选择保存或输入名称时保留该流程，完成后再返回。服务端先广播退出原因，收到对方的接收确认后通知退出方关闭连接；对方失联时有超时保护。
8. 对局中退出先确认并暂停双方棋盘，取消则继续。确认后中止本局，双方分别选择是否保存已有落子作为未完复盘，处理完返回主界面。主动退出不计为对方获胜。
9. 网络中断后锁定棋盘，只能保存本机已确认落子或放弃，再返回主界面。本版不重连，不恢复联网残局。强杀或断电时被终止的那一端不能弹出保存框；另一端仍可保存。中断瞬间两端最后确认步数可能不同。
10. 联网复盘位于本机 `data/replays`，从主菜单“复盘”进入；列表显示联网及黑胜/白胜/平局/未完。可独立播放和删除，删除不影响朋友电脑上的副本。

11. “请求悔棋（一回合）”：先确认发起，再由对方同意。撤回申请者最近一手，若对方已应答则连同应答一起撤回，让申请者重新落子。尚未落子、棋局结束或其他询问中禁用。拒绝后申请者看到“对手拒绝了你的悔棋请求”两秒，原棋局继续。
12. “认输”：先询问确定与否，双方棋盘暂停；取消则继续，确认后服务端判定另一方获胜，再进入保存与再来一局流程。复盘记录认输原因，播放到最后一步显示获胜结果，不伪造五子连线。零步认输也可保存复盘。
13. 等待室房主可点击“复制连接信息”，复制IP和端口。上次填写的有效地址、加入端口和创建端口分别记在 `data/network.ini`，下次自动填入；连接失败提供“重试”且保留输入。朋友开局前离开会告知房主并继续等待；房主主动关闭房间则告知朋友并返回联网菜单。退出对局、拒绝再战、取消再战和意外掉线各自有明确原因提示。

界面中的“是/否/保存/取消”等继续使用原按钮素材。网络线程只收发消息；EGE主线程渲染和处理输入。4字节网络序长度将TCP流拆成消息，服务端复用棋局规则，验证局号、步数、轮次与问答编号。每3秒心跳、15秒无数据判定中断；连接阶段约8秒连接超时、10秒整体等待上限。服务端监听成功通过事件通知游戏，避免慢电脑上启动竞争。

本版联网复盘格式为 `GOMOKU_LOCAL_REPLAY 4`，`MODE ONLINE`，`HUMAN 1/2`记录本机执棋颜色；房主黑、朋友白，`RESULT 0`表示未完。新增 `REASON`：0未记录、1连五、2平局、3认输、4主动退出、5连接中断、6协商重开；新增 `STARTED` 为服务端开局时的Unix时间戳。复盘详情显示本机执棋、对局时间、总步数、结束原因和未完不可续局提示。只记录确认的历史，不记录IP、房主座位口令等连接资料。v1/v2本地及v3联网旧存档继续兼容；没有时间或结束原因时显示未记录，不推断补造。旧版程序无法读取v4联网复盘。

## Dev-C++编译与发给朋友

- 已生成 `Gomoku.exe`、`main.exe` 和 `GomokuServer.exe`。普通玩家运行 `Gomoku.exe`，不需要手动启动服务端。
- 使用Dev-C++完整重编译：先打开 `GomokuServer.dev` 编译服务端，再打开 `Gomoku.dev` 编译游戏。两个工程都使用原TDM-GCC 4.9.2 64位编译器。不要把 `server_main.cpp` 当作游戏工程的第二个入口参与链接。
- `build.ps1` 用同一个Dev-C++编译器依次构建服务端和游戏。源码为GBK、中文注释，界面宽字符串采用Unicode转义。新增运行代码全部是C++11/Windows API；Python/PowerShell仅是开发及测试脚本。
- 发给朋友：`Gomoku.exe` + `GomokuServer.exe` + **实际完整的assets文件夹**。不要只复制本工作区的assets目录联接。`data`可选，不带则程序自动创建空目录；带上则包含已有棋局。
- 两人都可以当房主，所以双方建议都携带服务端exe；只作为加入者时不会启动它。运行机器需为兼容的64位Windows。编译器运行库采用静态链接。
- 本机测试可启动两个不同文件夹中的游戏，朋友端填写 `127.0.0.1`；跨电脑填写房主Tailscale地址。本机回环测试不等同于跨电脑防火墙/Tailscale实测。

## 新增代码与验证

- `network_protocol.h`：服务端状态机、快照编码与验证。
- `network_transport.h`：非阻塞socket、长度分帧、后台线程和收发队列。
- `server_main.cpp`：双人房间、房主座位校验、广播、心跳和退出清理。
- `online_ui.h`：建房/加入、询问、双方独立保存和联网界面。
- `match_metadata.h`：结束原因、结果一致性验证和对局时间显示。
- `tests/network_tests.cpp`：轮次、旧消息、询问锁定、重开拒绝、双方保存屏障、胜负、退出、v3未完复盘验证。
- `tests/network_integration.py`：真实TCP服务端，分包/粘包、满房、版本错误、双端一致、重开、再战、断线与禁止中途加入。
- `tests/online_ui.ps1`：两个真实EGE窗口，各自使用独立测试目录，验证建房、加入、保存、拒绝提示、房主退出后朋友继续命名、复盘及窗口关闭流程。
- 现有 `tests/stage_tests.cpp` 和 `tests/stage_ui.ps1` 用于本地、人机、存档及复盘回归。测试不会操作用户 `Gomoku/data` 中的棋局。
- 增强版检查：`tests/network_v2_tests.cpp`（悔棋、认输、保存阶段、拒绝/取消、v4/旧档兼容）、`tests/network_v2_integration.py`（真实TCP退出送达确认和原因保留）、`tests/network_v2_ui.ps1`（真实双窗口交互）、`tests/network_extras_ui.ps1`（复制信息、等待室离开重入、预览及拒绝提示）。历史 `online_ui.ps1` 使用旧版按钮坐标；新版以v2界面测试为准。
