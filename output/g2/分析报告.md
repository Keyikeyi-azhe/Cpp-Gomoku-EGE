# Gomoku2 可视化分析报告

双击 `index.html` 即可离线使用。建议先看“模块关系”，再看“函数调用”，最后看“枚举怎么用”和“变量怎么变”。

## 覆盖范围

- 当前 Gomoku2 的 14 个 `.cpp/.h` 文件，未修改源码、素材或存档。
- 164 个函数，13 个结构体/类，7 类枚举，86 个枚举值。
- 476 处可解析的项目内部直接调用，6 处函数地址引用。
- 312 处枚举值使用，493 处核心变量使用。
- C++ 语法树错误 0 个；学习图所有内部边端点均完整。

## 怎么读箭头

- 模块包含图 A → B：A 包含 B，只是编译依赖。
- 模块调用图 A → B：A 中的函数调用 B 中的函数。
- 函数图 A → B：A 的函数体内有 B 的直接调用；并非每次进入 A 都执行 B，需看条件。
- 虚线：传入函数地址，可能稍后由系统、线程或排序过程调用；不是立即调用。
- 枚举图 函数 → 常量：函数比较、赋值、case 或传参时使用常量。
- 变量图 左侧 → 变量：读取；变量 → 右侧：赋值/增减或修改方法调用。

`game.turn`、`game.result` 等按类型成员归组，包含 shown、record.game 和其他 LocalGame 实例。不能把所有这些边都理解成只修改全局 game；每处证据保留实际对象和源码行。

## 提取方法与限制

按 graphify 技能完成检测、AST 提取、图构建、社区分析、诊断、HTML/JSON/报告导出与 manifest。源文件为 GBK，分析用 UTF-8 副本保持原行号。又用 tree-sitter C++ 补充调用条件、枚举、变量和独立学习视图。

图是静态分析，不是运行日志。跨线程、网络消息与服务端路径在操作路线中以学习归纳 INFERRED 标记。无法可靠定位的函数调用没有凭同名猜测补线；713 处系统/API、标准库或静态无法解析的调用单独保留在“学习关系数据.json”的 unresolved 字段。

原生 graphify 图：417 个提取节点、770 条原始关系。诊断有 24 条未声明端点关系、2 组同端点关系合并、1 条自环。这些问题没有隐藏，详细证据见 graphify-out/graph_health.json 与 原始端点问题.json。自环对应递归；合并分别发生在类型引用与构造方法关系中。学习图独立保留每个源码使用位置，不依赖原生图的合并边。

graphify 原生 `graph.html` 使用外部可视化脚本，可能需要联网；主入口 `index.html` 不需要服务器、不需要联网，也不读取外部文件。

代码 AST 没有调用语义 API：graphify 记录输入/输出 token 均为 0。宿主编写学习解释和页面的 token 不在该统计中，不能据此认为整个任务无 token 消耗。
