CHAPTER 01

先认清你正在读的程序

先建立整体地图，再钻进代码。不要从 main.cpp 第一行开始逐字硬啃。

本书只依据工作区 Gomoku3 的当前源码。Gomoku、全AI五子棋、材料里的示例和 tests 下的历史运行副本都不属于本书的运行源码范围。tests 是验证材料，不会被链接进游戏。

实际编译单元 | 作用

main.cpp → Gomoku.exe | 图形客户端，包含其余模块；单文件编译通常输出 main.exe。

server_main.cpp → GomokuServer.exe | 独立控制台程序；房主通过隐藏子进程启动它。它有自己的 main。

8 个 .h 文件 | 不仅声明类型，也定义很多函数；经 #include 展开后一起编译。Compile=0 不等于“不参与程序”。

build.ps1 / 两个 .dev | 确认编译命令和链接库；两个 main 不能混在同一次链接中。

证据：build.ps1 分两次调用 g++；Gomoku.dev 仅 main.cpp 的 Compile=1；GomokuServer.dev 仅 server_main.cpp 的 Compile=1。当前 10 个运行源码文件共 2608 行（含注释、空行）。旧 exe 的修改时间早于部分源码，不能据其文件名断言它与当前源码一致。

CHAPTER 02

读这份代码需要的 C++

每个语法点，都对应你马上会遇到的一行代码。

语法 / 类型 | 在本工程里怎样理解

struct / class | 把数据和操作放在一起。struct 默认 public；class 默认 private。AISearch 的 public: 以前是内部实现。

对象与成员访问 | LocalGame game 创建对象；game.turn 访问成员；self->answer 通过指针访问成员。

构造函数 | 名字与类型相同，无返回类型。LocalGame() 自动调用 reset()，并不是每次落子都重新构造。

初始化列表 : | AIEntry():key(0)... 在进入函数体前初始化成员；初始化顺序由成员声明顺序决定。

const T& | 只读引用：不复制整个对象，函数也不能通过此引用修改对象。

T& 输出参数 | take(AIPoint& point,int& gen) 可把结果写回调用者的变量；返回 bool 另外表示是否成功。

const 成员函数 | wins(...) const 不改当前对象的成员；它仍可以使用局部变量 count。

指针 * 与取地址 & | volatile LONG* cancel 指向共享标志；&cancelled 取得该变量地址。NULL 表示没有对象/句柄。

vector<T> | 可增长数组；push_back 追加、back 看末尾、pop_back 删除末尾、clear 清空。下标从 0 开始。

string / wstring | 字节串与宽字符串。Windows 下 wchar_t 通常为 UTF-16 代码单元；24 个代码单元不严格等于 24 个 Unicode 字符。

size_t | 容器长度/索引常用的无符号整数。size()-1 在空容器时可能下溢，所以倒序搜索先转 int。

枚举 enum | 给整数起名字。Page、Dialog、NetPhase 各管不同状态，不能混为一个编号空间。

|| 与 && | 从左到右短路求值。place 先判越界，后访问 cells，避免越界读取。

语法 / 类型 | 在本工程里怎样理解

?: / ! | 条件 ? 值1 : 值2；! 表示逻辑取反。!result 意为结果为 0，即未结束。

static / inline | static 成员函数无 this，可给线程当入口；局部 static 只初始化一次。inline 也解决头文件同一定义的链接问题，不保证机器码必定内联。

lambda [](...){} | 这里用于排序。candidates 的 a.score>b.score 表示高分排在前面。

static_cast / reinterpret_cast | 前者进行显式类型转换；后者把地址/句柄按另一种类型解释，常见于 Win32 接口。

位操作 ^ << >> | | ^ 异或用于随机数和哈希；<<、>> 在整数上可表示移位，在流上表示输入输出。

HANDLE / HWND / SOCKET | 系统资源的标识，不能把它们当普通 C++ 对象随意 delete；分别用对应的关闭函数。

三个“返回值”要分开

place 返回 true 表示“这一步成功放下”，不是“赢了”；是否赢要读 game.result。parseRecord 返回 true 表示校验通过，记录从 output 引用取。线程函数 run 返回 0 表示线程退出，其计算答案写在 answer 中。

作用域与同名变量

main.cpp 的全局 game 是界面当前棋局；AISearch::board 是搜索副本；ReplayPlayer::board 是播放到当前步的展示盘；NetState::game 是网络权威状态中的棋盘。它们类型相同，但不是同一块数据。局部 r 在读档里可能是 GameRecord，在棋盘循环里却是行号，必须连同所在函数读。

小练习

为什么 3 - turn 能切换黑白？答：turn 只允许 1、2；3-1=2，3-2=1。若 turn=0，这个表达式并不会得到合法棋色，正确性依赖变量的取值约定。

CHAPTER 03

棋盘：从数据到判胜

打开 game_logic.h。这里只管规则，不画图、不联网，也不知道谁是人类。

变量 / 成员 | 含义与取值

Move.row / Move.col | 一手棋的行、列，范围 0..14。

Move.stone | 这手的颜色：1 黑，2 白；Move 是一次历史记录。

LocalGame.cells[15][15] | 当前盘面：0 空、1 黑、2 白。第一维是行，第二维是列。

LocalGame.turn | 下一手轮到谁；未终局时为 1 或 2。终局时不再翻转，保留最后落子方。

LocalGame.result | 0 未结束；1 黑胜；2 白胜；3 平局。

LocalGame.moves | 按时间顺序保存的 Move 数组，同时支撑悔棋、存档和复盘。

LocalGame::reset

game_logic.h : 24

作用与接口  无参数、无返回值；恢复空棋盘。

LocalGame::wins

game_logic.h : 32

作用与接口  输入最后落点 row、col；返回这一点所在的线上是否有至少五颗同色子。

执行顺序  先取当前格颜色；空格返回 false；对四个方向逐一从中心向两端走，遇到边界、空位或异色停止；累计>=5 返回 true。

参数与局部量  directions[4][2] 是方向增量；d 是方向下标；stone 是本格颜色；count 从 1 算自身；sign=-1/+1 是两端；r、c 是扫描中的坐标。

对照源码时留意

它不检查入口 row/col 是否越界；调用者先保证合法。方向 (1,0) 在行列坐标中是竖直，源码“右”的注释不可照抄。六连也算胜，不含禁手规则。

图：中心金圈是最新一手。箭头示意另一条待检查的竖线；四条线逐一检查，任一方向达到 5 即获胜。

LocalGame::place

game_logic.h : 54

作用与接口  输入 row、col；true 表示落子成功，false 表示状态没有被正常落子流程更新。

执行顺序  拒绝已结束、越界、占用；写 cells；构造 move 并追加历史；先判胜，再判满盘，最后才交换 turn。

参数与局部量  move 是当前这一步 {row,col,turn}；225=15×15。

对照源码时留意

胜利与满盘同时发生时，先判胜。wins 不会改 result，place 才负责落地终局状态。

图 3  place 的判断顺序

LocalGame::undo

game_logic.h : 66

作用与接口  撤掉最后一手；终局或无历史时返回 false。

执行顺序  复制 moves.back；pop_back 删除历史；将原落点置 0；turn 恢复为这手的颜色。

参数与局部量  move 是被撤回的一手。

对照源码时留意

不支持撤销已经结束的棋局。AI 回合悔棋由上层多次调用这里实现。

手算一局 | 关键变量变化

刚创建 | turn=1，result=0，moves.size()=0

place(7,7) | cells[7][7]=1，moves[0]={7,7,1}，turn=2

再 place(7,7) | 返回 false，所有棋局字段不变

place(7,8) | cells[7][8]=2，moves.size()=2，turn=1

undo() | 删去白棋，turn=2，moves.size()=1

读完自测

请遮住源码写出 place 的五步顺序，再解释为什么不能先把 turn 翻转后再存 Move。答案：那会把历史里的落子颜色记成对方。

ai_engine.h : 153

对照源码时留意

示意分数：-3 > -8，所以选 B。每换一方就取负号；Alpha-Beta 的窗口也必须从 [alpha,beta] 变为 [-beta,-alpha]。

Alpha-Beta：什么时候可以不再看

alpha 表示当前已找到的最好下界；beta 是对手传来的可接受上界。当某候选 score 使 alpha>=beta，后面的同层候选已经不能改变上层决策，可直接 break。例如窗口 alpha=3、beta=5，某分支得7后，alpha变7，就不必再搜索该节点其余点。

递归表达式是 -search(3-stone, depth-1, -beta, -alpha, ply+1)。前面的负号是换视角；负号后的窗口顺序也反转。胜利返回 WIN-ply，偏好较早赢。根 choose 每个候选仍使用完整 [-WIN,WIN] 窗口，不应描述成根节点共享不断收窄的 alpha。

置换表：缓存也要说明“这是什么结论”

flag | 读写的含义

0 精确值 | 本次 best 严格落在原窗口内部；命中且深度足够可直接使用。

1 下界 | best>=oldBeta；只能保证至少这么好。命中后提高 alpha。

2 上界 | best<=oldAlpha；只能保证不比这个更好。命中后降低 beta。

表槽由 key%65536 决定，槽位冲突会覆盖，但读取还要完整比较 entry->key==key。深度不够仍可借用最佳点 preferred 排序，不可直接借用分数。表和 history 在一次 AISearch 内复用；下一次 AI 落子会创建新的 AISearch，并非全局永续缓存。

CHAPTER 09

联网规则：两个人共享同一个裁判

打开 network_protocol.h。先不管 socket，先把它当成“输入命令，更新状态”的普通 C++ 模块。

联网棋局由服务端的 NetState 裁决。客户端只提交意图，服务端验证后向双方广播 STATE。这样能避免两边各算各的，出现黑方看见落子、白方却没有收到的分歧。网络延迟期间，客户端不会先把请求落成正式棋子。

TCP：收到的是字节，不是一条条消息

打开 network_transport.h。把“如何运字节”和“这一手能不能下”分开理解。

TCP 保证的是有序字节流。一次 send 不保证对应一次 recv：一条消息可能分几次到达，多条也可能一起到达。本工程给每条正文前加4字节网络序长度，接收方根据长度从累积缓冲区拆出完整消息。

变量 / 成员 | 含义与取值

NetSocket.fd | 原始 SOCKET；INVALID_SOCKET 表示没有连接。

input / output | 尚待拆帧的接收字节；尚未完全发送的字节。不是消息队列。

received / sent | 最近成功收/发的毫秒时刻。received 用于15秒超时；sent 被记录但当前没有其他逻辑读取。

failed | queue 遇非法长度或缓冲超限时设true，pump 随后失败。

NetClient.mutex / thread / stopFlag | 保护消息队列的临界区；后台线程句柄；原子停止标志。

incoming / outgoing | 收到后等待UI取走 / UI提交后等待网络线程发送的完整字符串队列。

address / hello / port | 目标IPv4文本、建立连接后发出的握手正文、目标端口。

读完自测

重开与再战为什么都有“等待对方”？因为双方都要先完成自己的保存决定。重开用done数组，正常终局再战用again数组；服务端不会因为一方先完成就清空另一方还在保存的旧盘。

答案与对应函数

1. 六连满足 count>=5，算赢；终局后 undo 返回false。看 LocalGame::wins / undo。
2. (row,col)=(7,7)，cell=112；若偏移平方超过900，boardCell 返回-1。
3. lastHumanMove 返回下标1；while(size>1)撤掉黑方应答和白方那手，只留最早黑棋；轮到白。
4. 少一行会在读取或MOVE格式校验失败；第一手棋色为2会在 stone!=r.game.turn 处失败。
5. 默认下一手原定4000；2000暂停时还剩2000；8000恢复后deadline=10000。
6. updateAI 会回收旧线程，但gen不匹配，拒绝落子；需要时再发新任务。
7. NetState::apply 检查r!=round拒绝；服务器回 EVENT INVALID 和当前STATE，UI重新对齐。

i/j/k 通常是局部循环下标，含义随容器变化；r/c 或 row/col 通常是行列，但 parseRecord 的 r 是记录对象。s 有时是字符串，有时是状态或棋色，必须看类型。out/o 是输出字符串流，in/input 是输入流，extra 用来检测本来不应该出现的尾随字段。bool ok/loaded/alive 只是当前步骤的成功判断，并不自动证明整个系统状态正确。

std::min/max 用于夹取范围；sort 按比较函数排列；find 检查容器成员，string::find 找子串；substr 取一段；erase 删除一段；resize 改长度；empty 判空；size 取数量；c_str/data 取交给C接口的缓冲地址。memset/ZeroMemory 清内存，memcpy复制定长字节；sprintf/swprintf 格式化窄/宽字符串；sscanf拆IPv4；atoi/strtoul/wcstol把文本转整数。
